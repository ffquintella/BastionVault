# ── Pinned verifier ───────────────────────────────────────────────

# An unpinned verifier makes a verification claim unreproducible. The gate
# refuses a log from any other version, and CI installs exactly this one
# (`scripts/verify.py pin kani`). A bump is its own change, with a full
# (tier 2) run green before merge — never bundled with a code change.

# ── Harnesses ─────────────────────────────────────────────────────
#
#   name     the function in crates/bv-policy-core/src/proofs.rs. `make
#            verify-gates` fails if this list and the #[kani::proof] functions
#            there differ in either direction — a harness silently
#            disappearing is the failure mode a proof cannot report on itself.
#   kind     theorem  every assertion holds and every cover is SATISFIED
#            witness  a DEFECT WITNESS: no assertion, its covers reach a
#                     behaviour the code's comments say cannot happen.
#                     SATISFIED = the defect is still present (a known open
#                     finding, reported, not a failure). Any other cover
#                     status fails the gate on purpose: the fix landed, so
#                     replace the cover with the assert in the harness's doc
#                     comment and move the row to `theorem`.
#   set      fast     runs in tier 1 (every PR touching the core) and tier 2
#            slow     tier 2 only (nightly, release)
#   covers   how many kani::cover! the harness has. A cover deleted without
#            this column moving fails the gate: covers are the vacuity guards.
#   secs     measured verification time, informational. The fast/slow split
#            is by these numbers (see below), so re-measure when moving a row.
#   label    the theorem (docs/verification.md) or, for a witness, the finding
#            and the task that fixes it.
#
